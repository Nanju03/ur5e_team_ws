# 수평 진입 높이와 하강 속도 변경 — v15

[실물 사용법](real_robot.md) · [저장 경로 사용법](saved_physical_replay.md)

장애물 1번·목표 6번 실물 시험에서 19층까지 수직 적층은 정상이고,
20층의 수평 진입 중 **운반 중인 블록이 기존 탑에 걸린 현상**에 맞춘 변경입니다.
그리퍼 개폐 각도와 19/20층 전환, 임시 적재 순서는 유지합니다.

## 새로 놓는 방식

20층부터 기존의 목표 높이보다 **10mm 높은 위치로 수평 진입**합니다.
목표 X/Y에 정렬한 뒤 마지막 10mm를 수직으로 내려놓고 그리퍼를 엽니다.
놓은 뒤에도 먼저 10mm 올라가고 옆으로 빠집니다.
탑 위를 건너는 구간의 기존 120mm 여유는 유지합니다.

수평 진입이 끝나기 전에는 운반 블록과 받침 블록 사이의 충돌을 허용하지 않습니다.
기존에는 받침 접촉을 허용한 채 받침면 높이로 밀어 넣었지만,
새 경로는 정렬 후 마지막 수직 내려놓기에서만 해당 접촉을 허용합니다.
진입 도중 운반 블록의 모서리가 받침면보다 약 10mm 이상 높은지도 확인합니다.

19층까지는 위에서 내려놓는 방식을 유지합니다. 모든 수직 집기·놓기 하강은
아래 속도 구분을 적용합니다. 역방향 IK로 얻은 집기 경로도 같은 점들을 사용해
속도 구간을 나누므로 임의로 다른 자세를 연결하지 않습니다.

## 속도·가속도

| 구간 | 기존 속도/가속도 배율 | 새 속도/가속도 배율 |
| --- | --- | --- |
| 마지막 접촉 구간 밖의 수직 하강 | 0.05 / 0.05 | **0.20 / 0.20** |
| 집기·놓기의 마지막 40mm 이상 | 0.05 / 0.05 | 0.05 / 0.05 |
| 높인 위치에서 수평 삽입, 마지막 10mm 내려놓기 | 0.05 / 0.05 | 0.05 / 0.05 |
| 집은 뒤·놓은 뒤 처음 40mm 이탈 | 0.05 / 0.05 | 0.05 / 0.05 |
| 나머지 운반·상승·후퇴·재정렬 | 1.00 / 1.00 | 1.00 / 1.00 |

Cartesian 점 간격과 보간 여유 때문에 저속 구간은 정확히 40mm보다 조금 길 수 있습니다.
이번 1→6 오프라인 경로에서는 빠른 구간이 접촉 목표보다 최소 약 45mm 위에서 끝났습니다.
그리퍼는 기존처럼 열기 0.40, 잡기 0.73, 놓기 0.70→0.60rad를 사용합니다.

현재 실물 URDF의 팔 관절 6개 속도 한도는 각각 πrad/s(180°/s),
시간화의 가속도 기준은 각각 1rad/s²입니다. 따라서 배율에 따른 관절별 상한은 다음과 같습니다.

| 배율 | 관절 속도 상한 | 관절 가속도 상한 |
| --- | --- | --- |
| 0.05 | 약 0.157rad/s (9°/s) | 0.05rad/s² |
| 0.20 | 약 0.628rad/s (36°/s) | 0.20rad/s² |
| 1.00 | 약 3.142rad/s (180°/s) | 1.00rad/s² |

이는 각 관절의 설정 상한이며 TCP의 일정한 mm/s 속도가 아닙니다.
짧은 경로의 가감속, 실제 제어기 제한, 펜던트 배율에 따라 실제 속도는 더 낮습니다.
전체 작업 시간이 4배 빨라진다는 뜻도 아닙니다. 그리퍼 명령 완료·정지 확인과 접촉 속도는 유지합니다.

## 저장 경로를 조금 수정할 수 있는가

가능하지만 관절 기록의 숫자 몇 개를 바꿔 바로 재생할 수는 없습니다.
위치를 바꾸면 해당 구간의 IK와 앞뒤 연결을 다시 만들고, 속도 변경 후 시간화와
실제 제어기 보간의 속도·가속도·충돌을 확인해야 합니다. 바뀐 궤적·장면에 맞는 검사 결과와
체크섬도 새로 발급해야 합니다. 기존 자료를 복사한 새 버전으로 작업합니다.

이번 변경은 모든 배치에 적용되는 놓기 알고리즘과 하강 시간화를 바꾸므로,
기존 v13/v14 자료는 그대로 보관하고 **v15에서 전체 경로를 새로 계획**합니다.
기존 형식의 오프라인 사전 검사만 다시 돌려서는 10mm 진입 경로가 추가되지 않습니다.
GUI의 현재 정책 사전 검사 기능은 좌표 편집기가 아닙니다.

## 다음 실물 시험

1. 실제 블록·탑·장애물을 처음 배치로 맞추고 빈 그리퍼와 초기 팔 자세를 확인합니다.
2. 기존 GUI를 닫고 `./start_block_real_gui.sh`로 새 GUI를 엽니다. 드라이버 재연결은 필요하지 않습니다.
3. 장애물 1번·목표 6번을 선택하고 ③→④를 진행합니다.
4. RViz에서 20층부터 높은 수평 진입→짧은 수직 내려놓기와 위로 이탈 후 후퇴를 확인합니다.
5. 새 계획을 승인해 시험합니다. 기존 v14 궤적을 중단 지점부터 이어 재생하지 않습니다.

실물 동작은 이번 코드 작업에서 자동 실행하지 않았습니다. 오프라인 검증은 보정된 모델과
명목상 25mm 블록을 사용하며 실제 누적 높이·기울기·접촉 상태는 현장에서 확인해야 합니다.

## 설정 위치

높이·속도는 v15에서 적용한 값이며 현재 저장 정책은 `physical_nearest_target_buffer_v16`입니다.
v16은 이 동작을 유지하면서 [목표 가까운 임시 받침](near_target_buffer.md)을 우선 선택합니다.

| 파일 | 설정 |
| --- | --- |
| `ur5e_a3_grid/config/stack_blocks.yaml` | `side_entry_clearance: 0.010`, 하강 배율·최종 구간 기본값 |
| `ur5e_block_bringup/launch/block_task.launch.py` | 실물 진입 10mm·최종 40mm·하강 0.20을 확정 |
| `ur5e_block_bringup/ur5e_block_bringup/physical_stack.py` | `SIDE_ENTRY_CLEARANCE`, `APPROACH_CLEARANCE`, `ARM_SPEEDS`, 실행 정책 |
| `ur5e_a3_grid/src/stack_blocks.cpp` | 높은 수평 정렬·수직 내려놓기, 하강 경로 구분 |

실물 수치를 바꿀 때는 런치·검증 정책·GUI를 함께 맞추고 정책 버전을 바꿉니다.
공통 YAML만 바꾸면 실물 런치의 값이 우선합니다. 이전 저장 경로는 수정 없이 남깁니다.

## 오프라인 검증 결과

보정된 동일 모델에서 제어 플러그인을 제거하고, 실행 기능을 끈 MoveIt을 별도 ROS domain 174에
띄워 확인했습니다. 합성 관절 피드백만 사용하며 실물 목표·그리퍼 명령은 보내지 않았습니다.

| 장애물→목표 | 적층 | 충돌 검사 표본 | 결과 |
| --- | --- | --- | --- |
| 1→6 | 23층 | 450,388 | 통과 |
| 11→14 | 23층 | 602,046 | 통과 |
| 15→10 | 23층 | 643,652 | 통과 |

세 경우 모두 20~23층의 실제 보간 표본에서 수평 진입 여유가 약 9.999~10.001mm였습니다.
빠른 하강의 끝은 접촉 목표보다 최소 약 45mm 위였고, 놓은 뒤에는 먼저 10mm 수직으로
올라가는 것도 12회 확인했습니다. 속도·가속도는 정확한 quintic 보간의 최대값으로 확인했습니다.
전체 회귀 테스트는 **1,400개 통과**했습니다.

1→6의 새 경로에서 명령 궤적 시간 합은 약 **1,227초(20분 27초)**입니다.
기존 저장 자료는 약 1,295초였지만, 이는 다른 시점에 생성한 계획의 명목 시간 비교입니다.
실제 제어기·펜던트 배율·정지 확인·통신 대기는 포함하지 않으며 실물 시간 단축 측정이 아닙니다.
이번 변경만으로 5분 내 전체 적층이 가능해진 것은 아닙니다.

검증용 경로는 실물 라이브러리에 등록하지 않았습니다. 실제 초기 배치를 복구한 뒤 ④에서
실물용 새 계획을 만들고 확인·승인해야 합니다. 기존 1→6 원본 recipe·메타데이터 보존도 확인했습니다.
검증 기록은 `~/ur5e_team_ws/log/side_hover_fast_descent_20261105/`에 보관합니다.
