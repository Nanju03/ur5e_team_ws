# 이웃 대각선 60가지 자동 시험

[Gazebo 수동 사용법](gazebo.md) · [경로 저장 형식](saved_paths.md) · [전체 안내](../README.md)

**2026-11-06: 기존 대각선 경로는 사용자 요청으로 삭제했습니다. 새 시험은
`--jobs 4`로 서로 다른 네 배치를 동시에 계획·적층·저장할 수 있습니다.**
[1→6 단일 시험](gazebo_single_case.md)은 `--obstacle 1 --target 6`으로 선택합니다.
기존 보고서는 남아 있지만 그 안의 이전 성공 ZIP 링크는 삭제된 파일을 가리킵니다.

4열×6행 플레이트에서 장애물과 쌓을 칸이 **행 1칸·열 1칸씩 떨어진 대각선**인 모든 배치를
Gazebo 물리로 순서대로 시험합니다. 장애물·목표 역할을 바꾼 경우도 별도이므로 **60가지**입니다.
장애물 1개, 빈칸 0개, 목표 칸의 바닥 블록 1개와 공급 블록 22개로 **최종 23층**을 시험합니다.
11→14를 먼저, 14→11을 두 번째로 시험하고 나머지는 번호순으로 진행합니다.
기존 첫 성공의 증빙 로그만으로 시험을 건너뛰지 않습니다.

## 권장: 케이스별 병렬 실행

```bash
cd ~/ur5e_team_ws
./test_block_diagonals.sh --jobs 4
```

한 작업자가 한 배치의 **초기화 → 경로 계획 → Gazebo 적층 → 최종 탑 검사 → 경로 저장**을 맡습니다.
먼저 끝난 작업자가 대기열의 다음 배치를 가져갑니다. 60개 배치를 중복 배정하지 않습니다.
각 배치는 가상 로봇의 동작 순서를 유지하며 서로 다른 Gazebo에서 실행됩니다.
성공 경로 ZIP은 여전히 마지막 복귀·23개 블록의 위치 검사·파일 검증까지 통과한 경우에만 만듭니다.

처음 네 배치만 확인하려면 다음 명령을 사용합니다. 보고서에는 나머지 56개가 미시험으로 남습니다.
이후 `--max-cases 4`를 빼고 같은 명령을 실행하면 미완료 배치부터 계속합니다.

```bash
./test_block_diagonals.sh --jobs 4 --max-cases 4
```

| 작업자 | ROS domain | Gazebo master 포트 |
| --- | --- | --- |
| 1 | 60 | 11370 |
| 2 | 61 | 11371 |
| 3 | 62 | 11372 |
| 4 | 63 | 11373 |

`--jobs`는 1..8 범위이며 최대 domain 67·포트 11377까지 사용합니다. 항상 localhost만 사용하며
실물 domain 0, 수동 Gazebo domain 44와 분리됩니다. 작업자 슬롯이 사용 중이면 기존 작업을
종료하거나 조작하지 않고 시작을 거절합니다. 각 슬롯의 ROS context·토픽·서비스·액션·프로세스 잠금도 분리됩니다.

- `--jobs 4`: 동시에 처리할 **케이스 수**입니다.
- `--workers 2`: 한 케이스의 OMPL 후보 수입니다. 케이스별 병렬 실행에서는 기본값이 2입니다.
- `--physics-threads 1`: 각 Gazebo 물리 계산은 직렬이며 기본값도 1입니다.
- 기본 CPU 배분은 운영체제에 맡깁니다. 강제 고정이 필요한 경우만 `--pin-cpus`를 사용합니다.
  이 옵션은 SMT 형제 CPU를 같은 작업자에 묶고 여유가 있으면 물리 코어 하나를 남깁니다.
  이 PC의 강제 고정 시험에서는 초기 자세 정착 대기가 길어져 기본값에서는 사용하지 않습니다.

동시에 여러 모델을 생성할 때의 시작 부하를 줄이기 위해 **모델·제어기 시작과 배치 생성은 순서대로**
진행합니다. `waiting_startup`은 이 순서를 기다리는 상태입니다. 초기화가 끝나면 다음 작업자의
시작을 허용하고, 앞선 케이스의 경로 계획·적층은 계속 진행합니다. 초기 자세 검사와 0.005rad
실행 정착 기준, 충돌 검사, 모델·제어기 확인은 유지합니다.

결과는 기존 순차 시험과 섞지 않고 새 폴더에 저장합니다.

```text
~/ur5e_team_ws/log/gazebo_diagonal_case_parallel/
  report.html / results.csv / summary.json / state.json
  failed_cases.md / failed_cases.csv / failed_cases.json
  cases/obstacle_1_target_6/attempt_001/
    simulator.log / scene.log / run.log / result.json
  workers/worker_1/ros/          작업자 1의 ROS 로그
  workers/worker_2/ros/
  ...
```

통합 보고서에는 케이스별 작업자·ROS domain·진행 단계·성공 ZIP과 실패 원인이 표시됩니다.
성공 경로의 위치는 `saved_paths/gazebo/obstacle_<번호>_target_<번호>/<실행번호>/successful_path.zip`으로 같습니다.
ZIP에는 실제 배치와 함께 작업자 도메인·포트·병렬 설정을 기록합니다.

Ctrl+C를 누르면 진행 중인 모든 작업자가 **자신이 시작한 프로세스만** 정리합니다. 같은 명령으로
다시 시작하면 성공·판정한 실패를 건너뛰고 미시험·중단 배치를 초기 상태부터 다시 시험합니다.
기록된 실패만 다시 시험하려면 다음 명령을 사용합니다.

```bash
./test_block_diagonals.sh --jobs 4 --retry-failed
```

동시 작업자 수는 같은 폴더에서 `--jobs 2`, `--jobs 6`, `--jobs 1` 등으로 바꿔 재개할 수 있습니다.
로봇 모델·알고리즘·물성·케이스 범위·케이스당 탐색/물리 설정이 바뀌면 새 `--output-dir`가 필요합니다.
화면을 켜려면 `--show-gazebo`를 추가하지만 여러 창의 렌더링 부하가 생깁니다. 기본은 모두 headless입니다.

병렬 실행은 전체 배치의 처리량을 높이기 위한 기능입니다. 개별 배치가 더 빨라지거나 네 배 빨라지는
것을 보장하지 않으며, 완주한 배치 수/실제 시간을 기준으로 4개와 6개 설정을 비교합니다.

## 기존 방식: 한 번에 한 배치씩 순차 실행

기존 `start_block_gazebo.sh` 시작 터미널을 **Ctrl+C로 종료**한 뒤 새 터미널에서 실행합니다.

```bash
cd ~/ur5e_team_ws
./test_block_diagonals.sh
```

한 번 실행하면 초기화·계획·승인·적재·결과 저장·다음 배치까지 자동으로 진행합니다.
추가로 GUI의 ③·④·⑤·OK를 누르지 않습니다.
기본은 화면 없이 실행하지만 **실제 Gazebo 접촉·마찰·중력 시험**은 수행합니다.
Gazebo 창으로 보려면 아래처럼 실행합니다.

```bash
./test_block_diagonals.sh --show-gazebo
```

RViz도 필요하면 `--show-rviz`를 추가합니다. 별도 수동 배치 GUI는 열지 않습니다.
처음 한 배치만 자동 시험한 뒤 확인하고 싶으면 다음 명령을 사용합니다.

```bash
./test_block_diagonals.sh --show-gazebo --max-cases 1
```

전체 경우의 목록만 출력하는 명령은 시뮬레이터·ROS 노드를 시작하거나 시험 결과를 만들지 않습니다.

```bash
./test_block_diagonals.sh --list
```

이 실행기는 **localhost ROS 44 / Gazebo 11355** 전용입니다.
기존 Gazebo가 실행 중이면 그 프로세스를 종료하거나 조작하지 않고 시작을 거절합니다.
각 시험은 새 Gazebo에서 팔 초기 자세와 물체를 다시 생성합니다.
성공·실패 후 자기 시험 프로세스만 종료하므로, 실패 당시 팔이 블록을 잡고 있어도 다음 배치에 이어지지 않습니다.

## 성공 경로와 실패 목록

성공 경로는 수동 GUI와 같은 배치별 보관 위치를 사용합니다.

```text
~/ur5e_team_ws/saved_paths/gazebo/
  obstacle_11_target_14/<고유 실행 번호>/successful_path.zip
  obstacle_14_target_11/<고유 실행 번호>/successful_path.zip
  ...
```

성공 ZIP에는 원본 계획, 실제 전송 궤적, 팔·그리퍼 명령, 시작·끝 관절 상태,
모델·설정·장면과 실행 로그가 들어갑니다.
자동 시험에서는 `tower_verification.json`, `batch_verification.json`도 포함합니다.
기존 성공 파일은 덮어쓰지 않습니다. **계산 없이 저장 ZIP을 재생하는 기능은 아직 별도 구현이 필요합니다.**

진행 상황과 실패한 경우는 아래 폴더에 계속 갱신됩니다.

```text
~/ur5e_team_ws/log/gazebo_diagonal_tests/
  report.html              전체 60가지 진행표: 브라우저에서 15초마다 갱신
  failed_cases.md          실패한 장애물·목표·단계·원인·로그 링크
  failed_cases.csv         실패 배치만 표로 정리
  failed_cases.json        실패 배치만 기계 판독 형식으로 정리
  results.csv              미시험·중단을 포함한 전체 결과
  summary.json             성공·실패·미시험·중단 건수
  state.json               재개 정보와 시도 이력
  cases/obstacle_11_target_14/attempt_001/
    selection.yaml         이번 시도의 배치
    simulator.log          Gazebo·MoveIt 시작/실행/종료 로그
    scene.log              블록 배치 초기화와 계획 장면 설정
    run.log                계획·승인·적재 전체 로그
    tower_verification.json
    result.json            이번 시도의 최종 결과
```

`report.html`은 파일을 브라우저에서 열어 확인할 수 있습니다.
종료 시 터미널에도 실패 배치 전체와 실패 목록 위치를 표시합니다.
**미시험과 사용자 중단은 실패로 세지 않습니다.** 환경 오류·시간 초과·저장 오류는 실패 목록에서
계획/적재 실패와 구분합니다. 실패 배치는 넘기고 나머지 배치를 계속 시험합니다.
실패는 이번 시도와 설정에서의 결과이며, 해당 배치가 불가능하다는 수학적 판정은 아닙니다.
공통 환경 오류가 3건 연속 발생하거나 종료를 확인할 수 없으면 자동 시험을 중단합니다.

## 중단·재개·실패만 재시험

시작한 터미널에서 **Ctrl+C**를 누르면 현재 가상 동작을 중지하고 자기 Gazebo 프로세스를 정리합니다.
다시 같은 명령을 실행하면 **성공과 이미 판정한 실패는 건너뛰고, 미시험·중단 배치부터** 진행합니다.
중간까지 쌓인 탑을 이어 쓰지 않고 해당 배치를 처음부터 다시 시험합니다.

```bash
./test_block_diagonals.sh
```

기록된 **실패 배치만** 재시험하려면 다음 명령을 사용합니다. 성공·미시험 배치는 제외합니다.
새 시도는 `attempt_002`처럼 별도 폴더에 남으며 이전 실패 로그를 보존합니다.
재시험에 성공한 배치는 현재 실패 목록에서 빠집니다.

```bash
./test_block_diagonals.sh --retry-failed
```

코드·물성·로봇 모델·설정을 수정하면 기존 시험과 섞지 않도록 지문 검사가 재개를 거절합니다.
수정 후 새 시험은 별도 결과 폴더로 시작합니다. 성공 궤적은 계속 고유 폴더에 저장됩니다.

```bash
./test_block_diagonals.sh --output-dir ~/ur5e_team_ws/log/gazebo_diagonal_tests_v2
```

## 시간과 성공 판정

각 배치에서 기존 실행기의 전체 경로·하드웨어·충돌·현재 상태·물체 관측·중지 검사를 유지합니다.
시작 시 팔은 명목 초기 자세의 0.05rad 이내이고 모든 관절 피드백이 최신이어야 합니다.
첫 명령 전 힘 제어 그리퍼의 무부하 처짐은 정상 관절 범위에서 허용하며, 실제 측정 상태에서 경로를 계획합니다.
실행 중 팔 정착 기준은 기존 **0.005rad**로 유지합니다.
기록 폴더의 배치·모델·계획 ID와 23층 사전 검사를 확인한 뒤, 그 실행의 전체 경로만 자동 승인합니다.
④ 계획을 따로 한 번 실행하지 않고 실행기의 사전 계획을 한 번 사용합니다.

마지막 복귀까지 완료하고 `STACK_SUCCESS`가 나온 뒤에도 **바닥 블록을 포함한 23개 모두**의 위치를 확인합니다.
현재 위치와 **가상 시간 2초 이후**의 위치가 각 층의 기대 중심에서 10mm 이내여야 합니다.
이 확인과 전체 명령 완료 기록·파일 해시·ZIP 무결성까지 통과한 경우만 **성공·경로 저장**으로 표시합니다.
실행만 성공하고 저장에 실패한 경우는 **저장 오류**입니다.

기본 실제 시간 제한은 시작 3분, 배치 설정 3분, 계획 15분, 승인 후 적재 **2시간/배치**입니다.
로봇 속도·가속도·물성은 기존 Gazebo 설정을 유지합니다.
필요하면 `--planning-timeout 1800 --execution-timeout 10800`처럼 초 단위로 늘릴 수 있습니다.

이전 11→14 실행은 약 **52분** 걸렸습니다. 같은 속도라면 60가지에 약 **52시간**이 걸리며,
계획·재시작 시간과 PC 성능에 따라 달라집니다. 시험 터미널을 켜 두고 PC가 절전되지 않도록 설정합니다.
새 배치 시작 전 결과 폴더의 여유 공간이 2GiB 미만이면 미시험 배치를 남기고 중지합니다.

이 기능을 추가한 뒤의 **60가지 전체 물리 시험 결과는 아직 없습니다.** 실행하면 이 폴더에 실제 결과가 쌓입니다.
