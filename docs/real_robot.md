# 실제 UR5e·AG95를 연결해서 사용하기

[README로 돌아가기](../README.md) · [Gazebo 사용법](gazebo.md)

시작 대기와 실물 속도·가속도 설정은 **[실행 시간·속도 조절 안내](speed_and_timing.md)**에 따로 정리했습니다.

현재 기본 적층은 **바닥 블록을 포함한 19층까지 기존의 위→아래 놓기, 20층부터 측면 삽입**입니다.
탑 위를 이동하기 전에 그리퍼와 잡은 블록의 최저점이 기존 탑 상단보다 **120mm 이상** 높도록
상승하고, 적층 위치 위에서 정렬한 뒤 수직으로 내려옵니다. 측면 방식은 탑 바깥에서 손목을 눕힌 후
상승·이동하고, 측면 대기 위치로 내려온 뒤 마지막 구간만 수평 삽입합니다.
이 높이에서 도달할 수 없으면 낮은 경로로 대체하지 않고 계획을 거절합니다.

변경 적용 후에는 기존 GUI를 닫고 `./start_block_real_gui.sh`로 다시 여세요.
놓기 방식을 **19층까지 수직 / 20층부터 측면**으로 확인하고,
실제 블록을 처음 배치로 맞춘 뒤 **③ 배치 표시 → ④ 실물 집기·쌓기 경로 계획**부터 진행합니다.
기존 저장 경로는 실행할 수 없습니다. 드라이버 터미널은 다시 연결할 필요가 없습니다.

실제 팔과 그리퍼를 연결해 집기·임시 적재·쌓기를 실행하는 절차입니다.
각 시작 스크립트가 이 작업공간 환경과 **ROS domain 0**을 설정합니다.
이 문서의 명령은 사용자가 실물 작업장에서 실행하기 위한 안내입니다.

## 1. 로봇·네트워크·그리퍼 준비

현재 설정은 다음 장치를 기준으로 합니다.

| 항목 | 설정 |
| --- | --- |
| UR5e IP | `192.168.0.2` |
| 노트북 유선 IPv4 | `192.168.0.1/24` |
| AG95 USB-RS485 | `/dev/robot/dh_ag95_gripper` |
| 로봇 공장 보정 | `~/ur5e_team_ws/robot_calibration/ur5e_20261031.yaml` |
| 받침·어댑터 설정 | `~/ur5e_team_ws/physical_setup.yaml` — 16mm·0mm |

로봇 전원과 브레이크 해제를 확인하고 티치펜던트를 **원격 제어 모드**로 둡니다.
현재 런치 기본값은 `headless_mode:=true`이며 드라이버가 제어 프로그램을 직접 전송합니다.
e-Series의 headless 모드에는 원격 제어가 필요합니다.
([UR 공식 문서](https://docs.universal-robots.com/Universal_Robots_ROS_Documentation/kilted/doc/ur_robot_driver/ur_robot_driver/doc/hardware_interface_parameters.html))

LAN과 그리퍼 USB를 연결한 뒤 터미널에서 확인합니다.

```bash
ping -c 3 192.168.0.2
ls -l /dev/robot/dh_ag95_gripper
id -nG
test -r /dev/robot/dh_ag95_gripper && test -w /dev/robot/dh_ag95_gripper && echo "그리퍼 USB 접근 가능"
```

`AG95 configure failed: IO Exception (13): Permission denied`가 나오면 USB 권한을 확인합니다.
`id "$USER"`에는 `dialout`이 있어도 **현재 터미널의 `id -nG`**에 없으면 실행 세션에
그룹이 반영되지 않은 것입니다. `d -nG`가 아니라 **`id -nG`**입니다.
드라이버가 실행 중이면 Ctrl+C로 종료한 뒤, 드라이버를 시작할 터미널에서 먼저 실행합니다.

```bash
newgrp dialout
```

새 셸이 열리면 **같은 터미널에서** 다시 확인합니다.

```bash
id -nG
test -r /dev/robot/dh_ag95_gripper && test -w /dev/robot/dh_ag95_gripper && echo "그리퍼 USB 접근 가능"
```

`dialout`과 `그리퍼 USB 접근 가능`이 표시된 **이 셸에서** 아래의 드라이버 명령을 실행합니다.
`newgrp`는 해당 셸에 적용되므로 다른 기존 터미널에서 드라이버를 다시 시작하면 권한 오류가 반복될 수 있습니다.
로그아웃 후 다시 로그인하면 새 로그인 세션에도 그룹이 반영됩니다.

다른 로봇을 사용하면 공장 보정 파일도 해당 로봇의 것으로 맞춥니다.
드라이버 로그의 **Calibration checked successfully**를 확인합니다.
([보정 확인 방법](https://docs.universal-robots.com/Universal_Robots_ROS2_Documentation/doc/ur_robot_driver/ur_robot_driver/doc/usage/startup.html))

## 2. 터미널 1 — 드라이버·계획 서버 실행

팔과 그리퍼의 동작 범위를 비우고 비상정지를 사용할 수 있는 상태에서 실행합니다.
**연결 초기화 중 AG95 손가락이 움직일 수 있습니다.**

```bash
cd ~/ur5e_team_ws
./start_block_robot.sh allow_execution:=true use_rviz:=false
```

이 터미널은 계속 켜 둡니다. 자동 쌓기 작업은 별도로 시작해야 합니다.
기본 로봇 IP와 USB 경로를 명시하려면 같은 명령에 다음 인수를 추가합니다.

```bash
./start_block_robot.sh allow_execution:=true use_rviz:=false \
  robot_ip:=192.168.0.2 gripper_device:=/dev/robot/dh_ag95_gripper
```

위 두 명령은 같은 용도이므로 하나만 실행합니다. 이미 드라이버가 실행 중이면 새로 연결하지 않고
다음 뷰어·GUI만 엽니다. 스크립트 기본 `allow_execution`은 false이며, 여기서는 실행용으로 true를 명시했습니다.

## 3. 터미널 2 — RViz 열기

```bash
cd ~/ur5e_team_ws
./start_block_view.sh
```

이 창에서 실제 측정 관절 자세와 계획된 경로를 확인합니다.

## 4. 터미널 3 — 실물 GUI 열기

```bash
cd ~/ur5e_team_ws
./start_block_real_gui.sh
```

창 제목에 **실물 로봇 제어**가 표시되는지 확인합니다.
오른쪽 실행 터미널 위의 **로그 전체 복사**는 현재 작업의 저장 로그 전체를 복사합니다.
화면에서 잘린 앞부분도 포함하며, 실행 중이거나 오류로 중단된 뒤에도 사용할 수 있습니다.
이 작업공간의 `start_block_gui.sh`는 ROS 42의 가상 GUI이므로 실물 연결에는
반드시 **`start_block_real_gui.sh`**를 사용합니다.

GUI에서 팔·그리퍼 제어기가 **active**이고 팔 6축·그리퍼 관절의 최신 피드백이 들어오는지 확인합니다.
필요하면 별도 터미널에서 다음 읽기 명령으로 제어기 상태를 확인할 수 있습니다.

```bash
source ~/ur5e_team_ws/env.bash
export ROS_DOMAIN_ID=0
ros2 control list_controllers -c /controller_manager
ros2 control list_controllers -c /gripper/controller_manager
```

팔은 `scaled_joint_trajectory_controller`, 그리퍼는 `dh_ag95_gripper_controller`가 active여야 합니다.
`env.bash`만 source하면 기본 도메인은 42이므로 위처럼 상태를 조회할 때에는 0으로 바꿉니다.

## 5. 실제 배치 설정·집기 경로 계획

1. 실제 플레이트·공급 블록·장애물을 GUI와 같은 위치에 배치합니다. 목표 칸에는 바닥 블록 1개를 둡니다.
2. GUI에서 **장애물**, **쌓을 칸**, **빈칸**을 선택합니다. Gazebo 배치와 실물 배치는 별도로 저장됩니다.
3. **③ 선택 배치를 RViz에 표시**를 누릅니다. 이 버튼은 계획 장면을 갱신하며 실제 블록을 옮기지 않습니다.
4. **④ 실물 집기·쌓기 경로 계획**을 누릅니다. 경로 생성과 전체 충돌 검사가 끝날 때까지 기다립니다.
5. RViz에서 집기·임시 적재·회수·목표 적재를 포함한 경로를 확인합니다.

실제 집기·쌓기에는 **④ 실물 집기·쌓기 경로 계획**을 사용합니다.
별도 **블록 없이 팔 경로 계획 · 시운전**은 블록 없는 팔 경로 시운전용이며 잡기 동작을 수행하지 않습니다.
이전 GUI에서는 팔 시운전 버튼 앞에 ④가 붙어 있었으므로, 수정한 GUI를 새로 열어 확인합니다.
계획만으로는 팔·그리퍼가 움직이지 않습니다. 배치·보정·시작 자세가 바뀌거나 이전 방식으로 저장한
경로가 있으면 다시 계획합니다. Gazebo 경로 파일은 실물 실행에 사용하지 않습니다.

## 6. 실제 집기·쌓기 실행

1. 처음에는 **단계별 확인** 모드를 선택합니다.
2. 계획 후 표시되는 상단 **⑤ 실물 집기·쌓기 실행**을 누릅니다.
3. 실물 준비 확인창을 확인한 뒤 RViz에 표시된 구간을 살펴봅니다.
4. 상단 **OK**를 누르면 실제 팔 또는 그리퍼의 해당 구간이 실행됩니다. 다음 구간도 OK로 승인합니다.
   **전체 연속 실행** 모드에서는 전체 경로를 한 번 승인하면 이어서 진행합니다.

매 집기 전 대기 위치에서 **0.40rad로 열기 → 접근 → 0.73rad 잡기**, 놓을 때는 팔을 멈춘 상태로
**0.70 → 0.60rad 열기 → 후퇴**합니다. 임시 적재가 필요하면 다른 블록 위에 보관한 뒤 현재 위치에서 회수합니다.
11번 장애물·14번 목표의 검증 배치에서는 **10번을 1번 위에 보관 → 15번 적재 → 10번 회수·적재**입니다.
임시 위치는 계획 결과에서 확인합니다.

## 7. 중단 후 복구·종료

작업을 중단할 때는 GUI의 **중지**를 사용합니다. 비상 상황에서는 로봇의 비상정지를 사용합니다.
블록을 든 상태에서 중단했다면, 블록을 받치고 안전하게 분리한 뒤 그리퍼가 비었는지 확인하고
**안전 확인 후 초기 자세 복구**를 사용합니다. 복구도 표시된 경로와 상단 OK로 승인해야 움직입니다.
복구 완료 후 실제 블록을 초기 배치로 맞추고 **③ 배치 표시 → 실물 집기·쌓기 경로 계획**부터 다시 진행합니다.
중단 당시의 계획을 그대로 재실행하지 않습니다.

종료할 때는 작업을 중지하고 팔·그리퍼가 정지한 것을 확인한 뒤 GUI·RViz를 닫고,
드라이버 터미널 1에서 **Ctrl+C**를 누릅니다.

## 검증 범위

사용자는 변경 전 설정에서 **실물 10층까지 적재 성공**, 11층의 자세 전환 중 기존 탑 접촉을 보고했습니다.
이번 수정의 **19층까지 수직·20층부터 측면·상단 120mm 접근**은
실물 보정 모델에서 23층 전체 경로를 계획 검사했습니다. 새 경로의 실물 동작은 아직 검증하지 않았습니다.
이전 Gazebo 세 번 운반 기록은 당시 접근 조건의 결과이며 이번 높이·전환 규칙의 물리 시험은 아닙니다.
이후 사용자는 장애물 11번·목표 14번에서 Gazebo 23층 전체 적재를 완료했고 완료 로그도 확인했습니다.
이는 실물 시험과 구분합니다. Gazebo 실행 기록의 보관은 [성공 경로 저장](saved_paths.md)에 정리했습니다.

## 승인 대기 중 상태 변화 오류

`[air_task-1]`과 `전체 경로 … 163개 구간`이 표시되고 계획 종류가 `empty_hand_stack_pattern`이면
블록 없는 팔 경로를 선택한 상태입니다. 실제 집기·쌓기는 **④ 실물 집기·쌓기 경로 계획**으로
다시 계획합니다. 해당 실행 작업은 `physical_stack`이며, 상단 실행 버튼도 **⑤ 실물 집기·쌓기 실행**으로 바뀝니다.

`Robot or gripper changed while waiting for path approval`는 승인 대기 중 관절 피드백이 오래됐거나
팔·그리퍼의 상태가 승인 조건에서 벗어나 실행을 중단했다는 뜻입니다. 팔의 시작 자세 허용 차이
0.001rad는 유지합니다. 새 로그의 `STACK_APPROVAL_STATE_CHANGED`에서 `feedback_fresh`,
`changed_arm_joints`, 그리퍼 검사 결과와 측정값·기준값·피드백 나이를 확인할 수 있습니다.
경로 종류를 바꾸는 것과 상태 변화 감시는 별개이며, 바뀐 자세로 실행하려면 현재 상태에서 다시 계획해야 합니다.

전체 연속 실행에서 `feedback_fresh: false`, `changed_arm_joints: []`, 그리퍼 변화 0으로
중단되던 경우도 수정했습니다. 전체 미리보기 생성·해시 계산 중에도 ROS 피드백과 중지 요청을
처리하도록 바꿨습니다. 팔·그리퍼 피드백의 **1초 기준**, 팔 시작 자세의 **0.001rad 기준**과
각 동작 전 검사는 유지합니다. 실제 피드백이 끊긴 경우에는 계속 중단합니다.

수정 후 다시 진행할 때는 단계별 시험에서 옮긴 블록을 GUI의 초기 배치와 맞추고,
**③ 배치 표시 → ④ 실물 집기·쌓기 경로 계획 → 전체 연속 실행 선택 → ⑤ 실물 집기·쌓기 실행 → OK**로 진행합니다.
연속 실행 승인 오류의 재현·수정 검증(로컬 검증 기록·공유 대상 제외)을 참고하세요.
