# 한 블록씩 계획·적층하기

[실물 사용법](real_robot.md) · [속도 설정](planning_optimization.md)

실물 GUI의 기본값은 **한 블록씩 계획·반복 실행**이다. 목표층을 미리 정하지 않는다.
현재 탑과 남은 블록을 읽고, 한 블록의 집기·이동·놓기·후퇴 경로만 계획·검사한다.
전체 연속 실행에서는 현재 블록을 움직이는 동안 다음 한 블록의 경로 생성·충돌 검사를 별도 프로세스에서 준비한다.
현재 블록이 놓기·50mm 후퇴까지 완료되고 실제 장면·관절 위치·설정이 예측과 일치하면 준비된 경로를 사용한다.
계산이 먼저 끝나면 다음 블록 계획 대기가 사라지고, 늦으면 남은 계산 시간만 기다린다. 첫 블록과 단계별 확인은 기존 순서로 준비한다.

## 이동 중 다음 경로 준비

기본 `incremental_prefetch:=true`는 **한 블록 모드 + 전체 연속 실행**에서 적용된다.
추가 GUI 조작은 필요 없다. 실행 중인 작업은 기존 코드를 계속 사용하므로 작업 종료 후 다시 실행한다.
GUI·RViz·로봇 드라이버를 이 기능 때문에 재시작할 필요는 없다.

- `STACK_PREFETCH_STARTED`: 현재 경로의 검증된 완료 장면·관절 자세를 복사하여 다음 블록 계산 시작.
- `STACK_PREFETCH_HIT`: 실제 완료 상태를 확인하고 준비된 경로 적용. `wait_seconds`는 완료 후 남은 계산 대기와 인수 확인 시간이다.
- `STACK_PREFETCH_FALLBACK`: 별도 계산 실패 시 기존 방식으로 다시 계획. 작업 장면·설정·시작 자세 불일치는 자동으로 무시하지 않고 중단한다.

계산 프로세스는 domain 46·localhost 전용이며 실물 제어 클라이언트와 현재 장면 쓰기 기능이 없다.
동시에 한 블록만 미리 준비하고 계획 워커 2개·낮은 CPU 우선순위를 사용한다. Stop·실행 실패 시 해당 프로세스 그룹을 종료한다.
손가락 범위·손목 검사·시간/관절 표본 간격·속도·가속도·후퇴 높이는 유지한다.
후퇴 후 그리퍼를 더 여는 동작과 그때 필요한 정지는 유지하므로 팔을 무정지로 연결하는 기능은 아니다.

명령행에서 비교하려면 기존 `block_task.launch.py` 명령에 `incremental_prefetch:=false`를 추가한다.
속도나 경로 형상은 동일하며 계산을 이동과 겹치는 기능만 꺼진다.
오프라인 검증은 실물 처리량 측정이 아니므로 실제 절약 시간은 `STACK_PREFETCH_HIT` 로그와 실물 시험에서 확인한다.

2026-11-07 오프라인 확인: 장애물 19·목표 6의 동일 시작 장면에서 기존 경로와
팔 궤적점 135개가 일치했고, 명령 시간 17.1597초·검사 표본 13,238개도 같았다.
부모 실행 흐름 시험은 현재 블록의 17.16초를 대기로 모사한 동안 실제 다음 블록 계획·검사를
8.19초에 완료했고, 완료 후 상태 확인·경로 인계에는 0.203초가 걸렸다.
실물 팔은 움직이지 않았으며 이 수치는 실제 경기의 적층 수를 보장하지 않는다.
검증 자료는 작업공간 `log/throughput_offline_20261107/`에 있다.

## 실행 순서

```bash
cd ~/ur5e_team_ws
./start_block_real_gui.sh
```

1. 새 배치를 시작할 때만 실제 배치에 맞춰 **③ 선택 배치를 RViz에 표시**한다.
2. **한 블록씩 계획·반복 실행 (시간 제한 없음)**을 선택한 상태에서 **④ 실물 경로 준비 (한 블록 / 전체)**를 누른다.
   이 단계에서는 다음 한 블록의 경로를 준비하며 팔·그리퍼가 움직이지 않는다.
3. RViz에서 경로를 확인하고 **전체 연속 실행 → ⑤ 실물 집기·쌓기 실행 → OK**로 시작한다.
   첫 OK는 같은 배치·보정·모델·속도 정책에서 이후 블록도 계획·검사 후 자동 실행하는 세션 승인이다.
4. 한 블록을 완료할 때마다 `STACK_INCREMENTAL_PROGRESS`에 현재 층수와 남은 블록 수가 표시된다.
   **단계별 확인**을 선택하면 이후 블록도 모든 동작 구간에서 OK를 받는다.
5. 필요할 때 **실행 중지**로 멈춘다. 5분 타이머나 남은 시간에 따른 다음 집기 차단은 구현하지 않았다.

중간 탑에서 다시 시작할 때는 **③을 다시 누르지 않는다.** 이 버튼은 바닥 배치를 새로 만든다.
실제 탑·남은 블록이 현재 RViz 충돌 장면과 정확히 일치하고 그리퍼가 빈 상태일 때 ④로 다음 블록을 준비한다.
프로세스를 새로 시작하면 자동 실행 승인은 다시 받는다. 블록을 잡은 채 중지했다면 기존 복구 절차를 먼저 따른다.
GUI의 초기 자세 복구는 그리퍼 단계와 관계없이 현재 손가락 각도를 유지하며 팔만 복귀한다.
탑·남은 블록 장면과 잡힌 블록은 유지하므로, 다음 집기 전에는 실제 그리퍼가 빈 상태인지 확인한다.
빈 그리퍼인데 중단 잠금만 남아 있으면 **빈 그리퍼 확인 · 중단 잠금 해제**를 사용한다.
최신 빈 센서(1)·정지·부착 블록 없음을 확인하며 팔 이동과 장면 초기화는 하지 않는다.

## 짧은 후퇴와 다음 집기

- 집기 접근과 전체 수직 하강은 **1.00 / 1.00 배율의 한 궤적**이다.
  접근·하강 사이에 별도의 정지 목표를 보내지 않는다.
  빈 그리퍼는 가능한 한 현재 높이로 공급 칸 위에 정렬한 뒤 한 번에 내려온다.
  그 높이에서 공급 칸에 도달할 수 없으면 80mm 대기 높이를 다시 시도한다.
- 잡은 위치에서 먼저 수직으로 올린 뒤 목표 위로 직접 이동한다. 낮은 측면 대기점이나 초기 자세를 경유하지 않는다.
  상승·운반·놓기 직전 접근을 한 궤적으로 시간화하여 구간 경계의 강제 정지를 없앴다.
  기본 높이는 **운반 블록·그리퍼 최저점 기준 기존 탑 위 50mm**이며,
  직접 이동 구간에 더 높은 장애물이 겹칠 때만 그 장애물 위 20mm를 확보한다.
  손가락 0.690~0.733rad와 회전 중 형상의 높이를 함께 계산한다.
  손목을 눕힐 때도 실제 집는 지점(TCP)을 기준으로 직선을 계획한다.
  먼 공급 위치에서 탑 높이까지의 수직 상승이 불가능하면 먼저 80mm 수직 이탈한 뒤
  목표 쪽으로 올라가는 직접 경로를 시도한다. 탑의 여유 영역에 겹치기 전에는 50mm 상단 여유를 확보하며,
  전체 로봇·운반 블록의 충돌 검사를 통과해야 사용한다. 별도의 측면 대기점이나 정지 명령은 추가하지 않는다.
- 실측 파지각 기반 1차 열림(최대 0.70) → 0.60rad를 완료한 뒤, **빈 그리퍼의 가장 낮은 충돌 형상이 완성된 탑 상단보다 50mm 위**에 있도록 수직으로 후퇴한다.
  TCP 높이를 탑 위 50mm로 지정하는 방식이 아니다. 손가락 0.60±0.006rad 형상도 포함한다.
- 놓을 때의 마지막 20mm 하강은 별도의 **0.10 / 0.10** 저속 궤적이다.
  20층부터 10mm 높게 측면 진입한 뒤 내려놓는 방식도 유지한다.
  체크를 해제한 기존 전체 계획 모드는 120mm 통과 여유와 기존 집기 구간 분할을 사용한다.

| 동작 | 15층까지 속도 / 가속도 | 16층부터 속도 / 가속도 |
| --- | --- | --- |
| 빈 그리퍼 접근·집기 하강 | 1.00 / 1.00 | 1.00 / 1.00 |
| 잡은 뒤 상승·직접 운반·놓기 직전 접근 | 1.00 / 1.00 | 0.50 / 0.30 |
| 최종 20mm 놓기 (측면에서는 삽입·10mm 내려놓기) | 0.10 / 0.10 | 0.10 / 0.10 |
| 놓은 뒤 탑 위 50mm 후퇴 | 1.00 / 1.00 | 0.50 / 0.30 |

층수는 바닥 블록을 포함한다. **15/16층은 현재 속도 전환**, **19/20층은 자세 전환**이다.
그리퍼 작동과 장면 부착·분리는 팔이 정지한 상태에서 유지한다. 방향이 급히 바뀌는 곳은
관절 속도·가속도 한도에 따라 감속할 수 있으며, 한 명령이라고 일정 속도를 강제하지 않는다.
값은 `ur5e_block_bringup/ur5e_block_bringup/physical_motion.py`의 `FAST_LAYERS`,
`PICKUP_SPEED`, `LOW_TOWER_SPEED`, `HIGH_TOWER_SPEED`, `ARM_SPEEDS['approach']`에서 수정한다.
배율은 모델 한도에 곱해지며 펜던트 배율과 실제 제어기 제한도 적용된다.

집기 접근은 직선, 장애물 위의 짧은 상승·통과를 먼저 시도한다. 이때 빈 그리퍼 손가락 허용 범위와
회전 형상을 포함한 최저점이 경로상 장애물 상단보다 20mm 이상 높아지는 후보를 계산한다.
모든 높이·회전 후보의 짧은 접근이 실패한 뒤에만 큰 측면 경유점과 일반 탐색을 사용한다.
이 경로도 하나의 연속 집기 명령이며, 기존 충돌 검사 표본·손가락·손목 범위는 유지한다.

현재 한 블록 정책은 `physical_incremental_measured_fingers_v22`이다. v21 이하 자료는 보존하지만
새 한 블록 경로로 재사용하지 않는다. **기존 GUI를 닫고 다시 실행한 뒤 ④에서 새로 준비**한다.
검사 표본 간격·손가락 범위·손목 편차 범위를 줄이지 않는다. 불필요한 이동과 정지 경계를 줄여
궤적 길이·검사 표본·장면 변경 횟수를 줄이는 방식이다.
한 블록 검사에서는 미래 장면을 실물 MoveIt 서버에 반복 적용하지 않고 로컬 모델에서 검사한다.
현재 장면과 시작 장면의 일치·장면 체인·실행 중 감시는 유지한다. 전경 검사 모델은 재사용하며, 사전 계산은 별도 프로세스가 담당한다.
운반 중 바닥·지지 블록의 접촉 허용은 침투 깊이 0.01mm 이하로 제한하여, 연속 운반이 접촉 허용을 악용하지 못하게 한다.

## 실측 파지각과 놓기

집기 완료 각도를 최초 파지 기준으로 고정하고, 그 각도에서 0.005rad 열린 쪽부터
0.733rad까지를 운반 중 검사 범위로 사용한다. 기본 사전 검사는 0.690~0.733rad를 포함한다.
이 범위를 벗어난 파지는 팔을 정지한 채 부족한 손가락 형상만 같은 경로·장면에서
최대 0.005rad 간격으로 추가 검사한다. 같은 구간의 결과를 재사용하며, 실제 충돌·상태 변경·통신
지연이면 중단한다. 특정 장애물·목표 번호에 대한 예외 처리는 없다.

1차 놓기는 `min(0.70, 최초 파지각-0.010)`rad이다. 예를 들어 0.70401rad로 잡혔으면
0.69401rad로 먼저 연 뒤 기존 0.60rad까지 연다. 1차 열림이 닫힘 명령이 되지 않도록 하고,
실제 목표 도달을 확인한 뒤 장면 분리·2차 열림·팔 후퇴를 진행한다.
검증된 열림 범위를 확보할 수 없는 파지는 이동 전에 중단한다.

## 블록 선택과 종료

팔의 현재 위치와 목표까지의 XY 이동 거리가 짧은 후보부터 직접 집기 경로를 시도한다.
열린 그리퍼로 집을 수 없거나 경로를 찾지 못한 후보는 다음 후보로 넘긴다.
이 모드에서는 임시 적재를 추가하지 않는다. 모든 직접 집기 후보가 실패하면
`no_feasible_direct_pick`과 남은 개수를 표시하고 종료하며, 전체 성공으로 표시하지 않는다.
공급 블록이 모두 없어졌을 때만 `no_remaining_blocks`로 완료한다.

기존 임시 적재를 포함한 전체 계획이 필요하면 체크를 해제하고 ④에서 다시 계획한다.
명령행에서는 `block_task.launch.py`의 `incremental_stack:=false`가 기존 전체 계획 실행기를 선택한다.
이 한 블록 실행기는 실물용이며 Gazebo 일괄 시험 방식은 별도로 유지된다.

## 저장과 확인

GUI의 다음 블록 파일은 `~/.ros/ur5e_a3_stack/physical_next_plan_domain0_cube_plate_v1.recipe.json`이다.
기존 전체 경로 파일과 분리되며, 검사된 한 블록 자료는 `physical_path_library`에 보관된다.
설정·충돌 장면·시작 자세가 일치하면 재사용하고, 다르면 다음 한 블록을 새로 계획한다.
블록 사이에는 다음 블록의 **새 경로 계산·검사 시간**이 남는다. 계산을 동작과 겹쳐 실행하지 않는다.

완료한 배치 상태는 같은 폴더의 `incremental_session_<domain>_<id>.jsonl`에 매 블록 기록한다.
실행 중에는 기존의 시작 자세·제어기·센서·장면·중지 확인을 유지한다.
새 코드의 실제 로봇 속도·정확도·5분 적재 개수는 현장 시험으로 확인해야 한다.

현재 사용자가 조정한 배율은 `physical_motion.py` 기준으로 15층까지 1.00/1.00, 16층부터 0.50/0.30이다. 실행에는 이 파일 값이 적용되며 변경 뒤에는 새 프로필로 경로를 준비한다.
