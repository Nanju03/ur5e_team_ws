## 이번 로그의 확정된 사실

- 17:25:30에 시작한 실물 연속 실행에서 목표 8번에 최종 블록 9개를 옮겨 바닥 포함 10층을 완료했다.
- 218단계 `Place block 2 layer 11 descend` 중 `GRIPPER_SENSOR_STALE`이 최초 중단 사유였다.
  마지막 승인한 센서 표본 번호는 119456이다. 새로 받아들인 그리퍼 센서 표본의 나이가
  0.5초 미만이라는 조건을 충족하지 못해 팔 액션을 취소했다.
- 팔 액션 결과는 `ARM_ACTION_CANCELED`, status 5였다. 기록된 직전 추종 오차는 약 0.0016rad다.
  중단 후 최종 목표와 약 0.13rad 차이가 난 것은 내려오는 도중 정지한 위치의 잔여 거리다.
- 정지 확인 뒤 현재 부착 장면과 그리퍼에 블록이 남았을 가능성을 보존하는 잠금이 기록됐다.
  2번 블록을 놓는 이벤트는 아직 완료하지 않았다.

## 지연 원인 조사

해당 드라이버 로그에서 AG95 communication 오류는 확인되지 않았다. 중단 후 읽기 전용
8초 관측에서 장치 communication age는 최대 0.126초, 새 장치 표본 수는 118개였다.
ROS 콜백 최대 간격은 0.339초였다. 이 후속 관측으로 중단 순간의 통신 상태를 소급해 확정할 수는 없다.

실행 중 장면 변경을 확인하는 Python 계산을 별도로 측정한 결과 52KB 장면 한 번의
해시에 0.31~0.33초가 걸렸다. 이 계산과 센서 콜백은 같은 스레드에서 실행되므로,
장면 처리·스케줄링 지연이 겹치면 0.5초 센서 신선도 조건에 걸릴 수 있는 구조였다.
이는 확인한 처리 병목이며, 이번 순간의 USB 단절을 증명하는 로그는 없다.

## 수정

- 메쉬 전체 내용의 바이트를 매번 확인하되, 같은 내용의 정규화 계산은 재사용한다.
  메쉬 꼭짓점·삼각형·위치·충돌 허용 행렬 변경을 계속 감지한다.
- 장면 해시 표본은 캐시 적용 후 약 0.06초였다. 동작 중 센서 처리 스레드를 막는 시간을 줄인다.
- 그리퍼 센서 구독 큐를 최신 메시지 1개로 제한한다. 같은 센서 sequence의 반복 메시지는
  신선도 시각을 갱신하지 않는다.
- 다음 중단에는 `accepted_sample_age_seconds`, `callback_gap_seconds`,
  `reported_communication_age`, `observed_sample_sequence`, `last_rejection`을 남긴다.
  장치 갱신 중단과 메시지 처리 지연을 구분하기 위한 기록이다.
- 센서 제한 0.5초, 중단·취소, 파지 형상 검사, 승인·장면 확인은 유지한다.

## 복구

운영자가 그리퍼의 2번 블록을 지지·분리하고 빈 상태를 확인한다. 들고 있는 블록을 둔 채
초기 자세로 자동 복구하지 않는다. 이후 GUI의 안전 확인 후 초기 자세 복구 절차를 따른다.
중단 당시 배치에서 기존 경로를 이어 실행하는 기능은 없다. 옮긴 블록을 시험 초기 배치로
되돌리고 새 GUI에서 배치 확인 → ④ 새 경로 계획 → 검토·승인 순서로 시험한다.

새 장면 해시 정책이 적용돼 이번에 사용한 이전 검토 파일은 재사용하지 않는다.
