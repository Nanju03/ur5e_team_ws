# UR5e + DH 그리퍼 실습 패키지

Ubuntu 22.04 / ROS 2 Humble에서 UR5e와 DH Robotics AG-160-95-W-S를 사용하는 수업용 통합 소스다. UR 드라이버, 그리퍼 드라이버와 serial 라이브러리를 한 저장소에 포함했다.

현재 블록 쌓기 환경을 다른 노트북에 설치하는 절차는
**[다른 노트북에서 환경 복원](docs/other_laptop_setup.md)**을 따른다.
실행 스크립트·16mm 받침대 설정·사용한 UR5e 기구학 보정과 MoveIt 커밋 목록은
`workspace/`에 포함한다. 현재 잡기 명령은 **0.73rad**, 실물 팔 이동 중 추종 허용오차는
**0.1rad**이며, 잡기 명령 완료를 잡기로 간주한다.

## 포함된 구성

| 폴더 | 내용 |
|---|---|
| `Universal_Robots_ROS2_Driver/` | UR 드라이버·MoveIt 설정, `headless_mode` 기본값 `true` |
| `dh_ag95_gripper_ros2/` | `/gripper` namespace 분리를 적용한 그리퍼 드라이버 |
| `serial-ros2/` | 그리퍼 USB 통신 라이브러리 |
| `ur5e_block_description/` | 사용자 UR5e·AG95·작업대 모델 |
| `ur5e_ag95_moveit_config/` | 사용자 모델의 MoveIt 그룹·계획 설정 |
| `ur5e_a3_grid/` | STL 플레이트 배치 GUI·모서리 맞춤·블록 경로·기존 A3 도구 |
| `ur5e_block_bringup/` | 기존 실물 드라이버 연결·보정·저장 경로 검토와 팔 시운전 |
| `workspace/` | 실행 스크립트·실물 설정·기구학 보정·MoveIt 의존 소스 버전 |
| `development/validation/` | 개발 중 검증 도구와 과거 결과 기록 |
| `docs/` | 학생용 HTML·Markdown 실습 가이드 |

세 드라이버 소스 폴더는 일반 파일로 포함되어 있다. 서브모듈 설정이나 별도의 추가 clone은 필요 없다. 이 통합본의 실행·설치 절차는 **이 README와 `docs/` 가이드**를 따른다. 각 소스 폴더의 기존 README는 원본 참고 자료로 보존했다.

## 설치

ROS 2 Humble이 설치된 Ubuntu 22.04에서 진행한다.

```bash
sudo apt install \
  ros-humble-ur ros-humble-moveit \
  ros-humble-ros2-control ros-humble-ros2-controllers \
  ros-humble-xacro ros-humble-robot-state-publisher \
  python3-colcon-common-extensions python3-rosdep \
  python3-vcstool git build-essential cmake

mkdir -p ~/ur5e_ws/src
cd ~/ur5e_ws/src
git clone https://github.com/gamsaon/ur5e.git ur5e_ros2
```

rosdep을 처음 사용하는 노트북은 `sudo rosdep init`을 한 번 실행한다. 이미 초기화했다면 생략한다.

```bash
source /opt/ros/humble/setup.bash
rosdep update
cd ~/ur5e_ws
rosdep install --from-paths src --ignore-src --rosdistro humble -y
colcon build --symlink-install
```

## 팔 없이 AG95만 보정하기 — launch 실행

그리퍼 단독 보정은 GUI 없이 launch와 ROS 서비스로 실행한다. 각 터미널에서 같은 환경을 불러온다.
별도 `.sh` 파일은 사용하지 않는다.

```bash
unset AMENT_PREFIX_PATH COLCON_PREFIX_PATH CMAKE_PREFIX_PATH PYTHONPATH LD_LIBRARY_PATH
source /opt/ros/humble/setup.bash
source ~/ws_moveit2/install/local_setup.bash
source ~/ur5e_ws/install/local_setup.bash
export ROS_DOMAIN_ID=0 ROS_LOCALHOST_ONLY=1
```

그리퍼를 단단히 고정하고 블록 받침·손 제외·비상 전원 차단 준비를 확인한 뒤 터미널 1에서 시작한다.
**드라이버 초기화 중 손가락이 움직일 수 있다.** UR5e·MoveIt·RViz 노드는 시작하지 않는다.

```bash
ros2 launch ur5e_block_bringup gripper_calibration.launch.py \
  com_port:=/dev/ttyUSB0 execution_mode:=continuous
```

기본은 **그리퍼 단독, 힘 설정 20%, monitor**이며 파지 시험을 자동 시작하지 않는다.
위 명령은 한 작업의 각도들을 순서대로 실행하는 `continuous`를 명시한다.
코드의 기본 `step` 모드는 각도·추정 간격 미리보기 후 출력된 단계별 서비스에서 확인한다.
보정 노드가 기존 DH 드라이버를 자식 프로세스로 시작하고, 종료할 때 그리퍼 정지 확인 후 자식을 종료한다.
이미 드라이버가 실행 중이면 `start_driver:=false`로 재사용한다.

터미널 2에서 `/gripper_calibration/status`(`std_srvs/srv/Trigger`)의 JSON으로 준비·완료를 확인한다.
물리 준비 후 `/ready`(`std_srvs/srv/SetBool`, `data: true`)로 허용하고, Trigger 서비스
`/baseline` → `/grasp` → `/success` 또는 `/failure` → `/open` 순서로 시험한다.
성공·열기를 3회 이상 확인한 뒤 `/apply`로 추천값을 저장한다. 위 서비스 경로의 접두사는 모두
`/gripper_calibration`이다. **서비스 성공은 접수이며 완료는 `busy`·`phase`로 확인한다.**
상태 토픽은 `/gripper_calibration/state`(`std_msgs/msg/String`), 중지는 `/gripper_calibration/stop`이다.
단계별 확인이 기본이므로 이동 명령을 접수한 뒤에도 각 목표의 승인이 필요하다. 상태의
`pending_approval`에서 목표 각도·추정 간격을 확인하고, `approval_service`에 표시된
현재 단계 전용 Trigger 서비스를 호출한다. 이전 단계의 승인 서비스는 재사용하지 않는다.
`execution_mode:=continuous`는 해당 보정 작업의 단계들을 연속 진행하는 선택이다.
명령 전문과 1회 자동 빈 기준 측정 옵션은 [launch 보정 절차](ur5e_block_bringup/README.md)를 따른다.
기존 GUI 안내도 같은 문서에 참고용으로 보존했다. 실제 팔의 전체 자동 쌓기 실행 제한은 유지한다.

## 실행

로봇 IP는 `192.168.0.2`, 노트북 유선 IP는 `192.168.0.1`을 사용한다. 로봇을 켜고 **Remote Control** 모드로 둔다. 그리퍼 장치 고정과 USB 권한 설정은 [실습 가이드](docs/UR5e_DH_노트북_실습가이드.md#그리퍼-장치-고정)를 따른다.

**각 터미널에서 먼저** 새로 빌드한 작업공간을 불러온다.

```bash
source ~/ur5e_ws/install/setup.bash
```

터미널 A — UR5e:

```bash
ros2 launch ur_robot_driver ur_control.launch.py ur_type:=ur5e robot_ip:=192.168.0.2
```

이 통합본은 `headless_mode` 기본값이 `true`이므로 위 명령으로 Headless 연결을 사용한다. 기존 원본 작업공간이나 apt 설치본의 기본값을 변경한 것은 아니다. 반드시 **통합본을 빌드한 작업공간**을 source한다.

터미널 B — MoveIt 2:

```bash
ros2 launch ur_moveit_config ur_moveit.launch.py ur_type:=ur5e launch_rviz:=true
```

터미널 C — 그리퍼:

```bash
ros2 launch dh_gripper_driver dh_ag95_control.launch.py com_port:=/dev/robot/dh_ag95_gripper
```

기본 namespace는 `gripper`다. `namespace:=gripper`를 추가하지 않아도 팔과 그리퍼의 controller manager가 분리된다. 그리퍼 launch는 초기화 중 손가락을 움직일 수 있으므로 동작 공간을 비운 뒤 실행한다.

다른 터미널에서 열기·닫기:

```bash
# 열기
ros2 topic pub --once /gripper/forward_position_controller/commands std_msgs/msg/Float64MultiArray "{data: [0.0]}"

# 닫기
ros2 topic pub --once /gripper/forward_position_controller/commands std_msgs/msg/Float64MultiArray "{data: [0.93]}"
```

위 기본 실습 명령은 팔과 그리퍼를 각각 제어한다. 사용자 모델과 기존 GUI를 함께 쓰는 구성은 아래의 사용자 블록 쌓기 모델 연동 절차를 따른다.

## 사용자 블록 쌓기 모델 연동

이 작업공간에 추가한 `ur5e_block_bringup`은 위 기존 드라이버들을 재사용해 사용자
UR5e+AG95 모델을 연결한다. 실행은 `~/ur5e_ws/start_block_robot.sh`이며, 그리퍼
초기화 중 손가락이 움직일 수 있다. 자동 쌓기를 시작하지 않으며 MoveIt 실행은
기본 비활성화다. 옵션과 검증 범위는 [연동 안내](ur5e_block_bringup/README.md)를 따른다.

일반 쌓기 경로의 기본 놓기 방식은 **「10층까지 수직 / 이후 측면」**이다.
바닥 블록을 포함해 **10층까지 수직으로 놓고, 11층부터 측면**으로 놓는다.
25mm 블록 10층의 상단 높이는 **250mm**다. 장애물의 높이는 기존 **150mm**를 유지한다.
GUI의 **「모든 높이에서 수직」**을 선택하면 높은 층도 수직으로 놓는다.
선택 파일은 `placement_mode: side|vertical`과 `vertical_placement_layers: 10`(정수)을 저장한다.
이 층수 기준이 기존 `vertical_fallback_layers: 4`보다 우선하며, 10층 이하의 수직 경로가 막혀도
측면으로 바꾸지 않는다. 전체 경로 검사에 실패하면 실행하지 않는다.

현재 집기·쌓기의 닫힘 명령은 **0.73rad**, 놓기는 **0.70rad → 0.60rad** 순서다.
진입 구간은 속도 배율 **0.05**, 상승·후퇴·운반 등 나머지 팔 이동은 **0.20**을 사용한다.
실물 집기는 0.73rad 명령 완료를 잡기로 간주하며, 물체 잡힘·이탈 상태로 진행을 막지 않는다.
최신 관절·통신 피드백과 명령 완료, 검토한 그리퍼 형상은 계속 확인한다. 계획·가상 실행의 통과는
실물 파지 성공을 뜻하지 않으며, 날짜별 과거 검증 기록은 당시 설정의 결과로 보존한다.

### 공통 실행 방식 — 경로를 보고 OK로 실행

GUI 상단 **실행 방식**에서 다음 두 가지를 선택한다. 기본값은 **「단계별 확인」**이다.

| 실행 방식 | 확인과 이동 순서 |
|---|---|
| **단계별 확인** | 다음 한 구간을 RViz에 표시 → 상단 **「확인 OK · 표시한 경로 실행」** → 그 구간만 이동 → 다음 구간을 표시하고 다시 대기 |
| **전체 연속 실행** | 저장한 전체 경로를 RViz에 표시 → 상단 **「확인 OK · 표시한 경로 실행」** 한 번 → 마지막 구간까지 연속 이동 |

**플레이트 맞춤은 네 모서리의 X/Y 두 방향, 총 8개 맞춤 위치마다 반드시 멈춘다.**
연속 모드도 각 맞춤 위치까지의 경로를 따로 승인하고 판 조정 시간을 갖는다.
**「조정 완료 · OK로 계속 이동」**을 누른 뒤 수직 상승·높은 위치 회전·다음 맞춤을 진행한다.
자동 대기시간 후 출발하지 않는다. 단계별 모드는 기존처럼 각 구간의 OK를 기다린다.

**실행 버튼을 누른 뒤 첫 경로가 표시되어도 OK 전에는 이동하지 않는다.** 승인 버튼은
현재 표시된 경로에만 적용되며, 한 번의 승인으로 다음 단계까지 자동 승인하지 않는다.
취소·중지하거나 연결·로봇 상태·배치가 바뀌면 현재 승인을 계속 사용하지 않는다.

이 방식은 **장애물 위 XY 순회**, **일반 쌓기 형태의 공중 팔 경로**, **가상·실물 블록 쌓기의 팔·그리퍼**,
**별도 AG95 보정 창**에 적용한다. 팔의 공중 시운전은 그리퍼 개폐 명령을 보내지 않는다.
실물 집기·쌓기는 별도 검토 실행기를 사용하고, 기존 C++ 직접 실행기의 GenericSystem 제한은 유지한다.
그리퍼 보정에서는 팔의 3D 경로 대신
**그리퍼 목표 각도와 추정 간격**을 확인한다. 단계별 보정은 각 개폐 목표마다 보정 창의 OK가
필요하고, 연속 보정은 작업 순서·각도 범위를 한 번 확인한 뒤 해당 작업을 진행한다.
정지·오류 처리에서 움직이는 그리퍼를 **현재 위치에 유지하는 명령은 승인을 기다리지 않는다**.
드라이버를 새로 시작할 때의 그리퍼 초기화 동작은 별도로 주의한다.

업데이트를 빌드·설치한 뒤에는 **기존 GUI만 종료하고 다시 실행**한다. 이미 연결된 로봇
드라이버와 RViz는 유지해도 된다. 실제 실행에는 `allow_execution:=true`로 시작한 로봇 연결이
필요하다. 이전 저장 계획에는 새 구간 정보가 없으므로 **새 형식(schema 2)으로 다시 계획**한다.
새 계획을 만든 뒤 실행 방식만 바꾸는 경우에는 같은 계획을 사용할 수 있다.

```bash
~/ur5e_ws/start_block_gui.sh
```

경로가 표시된 뒤 저장에 실패하던 원인 중 하나는 MoveIt의 정상 좌표 변환 목록에서 여러 항목의
공통 대상 `world`를 중복 좌표로 오인하던 검사였다. 변환의 원본 좌표계를 기준으로 비교하고,
실제 충돌 형상에 영향을 주는 변환을 검사하도록 수정했다. 계획 저장·검증이 실패한 상태에서는
실행 목표를 보내지 않는다.

또한 팔·그리퍼의 관절 피드백이 서로 다른 메시지로 들어올 때, 그리퍼 메시지만 먼저 받은
계획 노드가 팔의 초기값 0을 현재 자세로 사용하던 경우를 수정했다. 계획 시작과 실행 직전에는
팔 6개·그리퍼 1개 관절을 각각 수신했고 모두 1초 이내의 유효한 측정값인지 확인한다.
일부 관절이 없거나 오래된 상태에서는 기본값으로 대신하지 않고 대기한 뒤 실패로 처리한다.

### 실물 집기·쌓기 — 검토한 팔·그리퍼 순서 실행

실물 GUI에서 **「실물 집기·쌓기 경로 계획」**으로 준비한다. 기존 **「블록 없이 팔 경로 계획」**과
별도 경로 파일을 사용한다. 실물 드라이버가 이미 연결되어 있으면 새로 시작하지 않는다.

1. 쌓을 홈의 바닥 블록 1개와 공급 블록·장애물을 실제 배치에 맞춰 선택한다.
2. **「실물 집기·쌓기 경로 계획」**으로 모든 층의 팔·그리퍼·운반 블록 충돌과 타이밍을 검사한다.
3. 저장한 전체 순서를 확인하고 실행 방식과 상단 실행을 선택한다. 실물 준비 확인창을 검토한다.
4. 단계별 모드는 각 팔 이동·그리퍼 명령을 OK로 승인한다. 연속 모드는 전체 순서의 OK를 한 번 승인한다.

| 구간 | 설정 |
|---|---|
| 집기 닫힘 | 0.73rad |
| 놓기 첫 열림 | 팔을 멈춘 채 0.70rad |
| 놓기 이동 여유 확보 | 같은 팔 자세에서 0.60rad 도달 후 후퇴 |
| 집기·놓기 마지막 진입 | 속도 배율 0.05 |
| 상승·후퇴·운반 | 속도 배율 0.20 |
| 팔 가속도 배율 | 0.05 |

속도 값은 MoveIt의 관절 제한에 대한 **배율**이며 m/s가 아니다. 짧은 구간의 소요 시간은
가속도 제한의 영향도 받는다. 모서리 맞춤 그리퍼 **0.65rad**, 기본 열림 **0.4rad**는 유지한다.

실행기는 모델·파일·배치·현재 관절·제어기 상태를 확인하고 검토한 순서만 전송한다.
잡기 명령이 완료되면 잡힌 것으로 간주한다. 물체 잡힘·이탈 센서 판정은 진행 조건에서 제외하며,
통신 단절·팔 추종 오차·검토한 그리퍼 형상 변경은 계속 검사한다.
놓기에서는 두 열림 동작이 끝나기 전에 팔이 후퇴하지 않는다. 힘 설정은 기존 드라이버 값을 유지한다.
물체 부착·놓기 장면은 검토 순서대로 갱신하며, 정지 후에는 잡고 있던 상태를 임의로 해제하지 않는다.

### cube_plate — 로봇 정면 배치와 모서리 홈 맞춤

현재 GUI와 `stack_blocks`의 기본 프로파일은 제공된 **`cube_plate.STL`**이다.
판은 **420×297×10mm**, 공급 홈은 **25.5×25.5mm·깊이 5mm인 24개**다.
STL의 mm 좌표를 ROS에서 `.001` 배율로 읽고, 실제 홈 중심 간격을 사용한다.
기존 `a3_grid` 직접 실행 도구의 균등 A3 격자는 이전 실습용으로 남아 있으므로,
그 도구의 칸 좌표를 이 플레이트의 실물 홈 좌표로 사용하지 않는다.

선택한 배치는 **로봇 베이스 중심에서 모델의 정면(`world +X`)으로 400mm**,
좌우 중앙(`Y=0`)에 판 중심을 두는 방식이다. 420mm 긴 변은 좌우 방향이고,
297mm 짧은 변은 로봇 앞뒤 방향이다. 따라서 베이스 중심에서 가까운 판 가장자리까지는
**251.5mm**, 먼 가장자리까지는 **548.5mm**이며 좌우 끝은 **Y=±210mm**다.
400mm는 베이스 외곽과 판 가장자리 사이 간격이 아니라 **중심 간 거리**다.

거리·방향 **26개 후보**에 대해 보정된 로봇 모델의 IK·충돌·관절 한계와 자세 여유를
비교했고, 이 배치가 설정한 평가 점수에서 가장 높았다. 이 기록은 초기 중앙 쌓기 가정의
검사 결과다. 현재처럼 쌓을 홈을 선택하면 해당 목표의 전체 경로를 새로 검사한다.
이는 검사한 유한 후보의 결과이며, 모든 후보 사이의 연속 최적화나 실제 전체 운반 경로의
완료·파지 성공을 보장하는 결과는 아니다. 후보 기록은
`~/ur5e_ws/validation/plate_placement_candidates.json`에 보존한다.

쌓는 곳은 GUI에서 **「쌓을 칸」을 선택한 뒤 누른 홈**이다. 그 홈에도 처음부터
**25mm 블록 1개**가 있으며, 이 블록은 옮기지 않고 **바닥 1층**으로 유지한다.
다른 공급 블록은 그 위 **2층부터** 쌓는다. 목표 홈·장애물·빈칸은 공급 대상에서 제외한다.
목표를 선택하지 않으면 일반 쌓기 경로를 계획·실행하지 않는다.

작업대 상판은 `world Z=800mm`, 공급·쌓을 홈 바닥은 **805mm**, 판 상판은 **810mm**다.
쌓을 홈의 바닥 블록 중심은 **817.5mm**, 윗면은 **830mm**다. 다음 블록 중심은
**842.5mm**이며, 이후 블록마다 **25mm**씩 높아진다.
로봇 아래에는 **16mm 높이의 사각 받침**을 visual·collision에 추가했다.
받침의 가로·세로 **200×200mm는 베이스를 덮는 모델용 대리 형상**이며 실측 치수가 아니다.
작업대 전체 충돌 상면을 높이던 방식은 제거했고, 실제 상판은 800mm로 유지한다.

맞춤 기준은 **판 외곽 꼭짓점이 아닌 모서리 홈 중심**이다. 단위는 **mm**,
좌표계는 **`world`**이며 표의 Z는 홈 바닥이다.

| 모서리 홈 | X | Y | 홈 바닥 Z |
|---|---:|---:|---:|
| A · 1번 | 310.9 | 150.0 | 805.0 |
| B · 4번 | 489.1 | 150.0 | 805.0 |
| C · 24번 | 489.1 | -150.0 | 805.0 |
| D · 21번 | 310.9 | -150.0 | 805.0 |

RViz에는 이 홈 중심에 A/B/C/D 박스와 좌표를 표시한다. **표의 Z=805mm는 TCP 명령 높이가 아니다.**
맞춤 중 그리퍼 관절값은 **0.65rad**, 그리퍼 전체 하단은 **판 상판보다 10mm 위**에서 멈춘다.
TCP 높이는 그리퍼 형상으로 계산하며, 두 홈 사이에서는 먼저 위로 상승한 뒤 수평 이동한다.
일반 작업의 기본 열림값과 가상 시작값은 **0.4rad**다.

기존 실물 드라이버·MoveIt에 연결할 화면이 필요하면 다음 두 명령을 **서로 다른 터미널**에서 실행한다.
첫 명령은 **viewer만** 열며 로봇·그리퍼 초기화나 이동 명령을 보내지 않는다.

```bash
~/ur5e_ws/start_block_view.sh
~/ur5e_ws/start_block_gui.sh
```

1. **빈 플레이트**로 시작하고 GUI 상단 실행 방식을 **「단계별 확인」**으로 둔다.
2. **「플레이트 맞춤 · 모서리 X/Y」**를 누른다. 실물 그리퍼가 0.65rad가 아니면 준비 확인창과
   상단 OK로 **그리퍼 준비 동작**을 먼저 승인한다. 팔은 현재 자세를 유지한다.
   준비 완료 뒤 측정된 0.65rad 자세로 모서리 홈 경로를 자동 계획한다. 계획만으로 팔이 움직이지 않는다.
3. **「⑤ 선택한 방식으로 팔 경로 실행」**을 누르고 준비 확인창을 검토한다.
4. RViz에서 현재 구간을 확인하고 **「확인 OK · 표시한 경로 실행」**을 누른다.
   초기 상승·자세 맞춤·모서리 접근도 별도 구간이다. 모서리 A/B/C/D와 X/Y 방향을 확인한다.
5. **팔이 홈 위에서 정지한 뒤** 그 홈에 맞춰 판을 놓는다. **손을 뺀 다음** 다음 구간의 OK를 누른다.
   판을 만지는 동안 다음 구간을 승인하지 않는다. X 맞춤 뒤에는 위로 올라가 90° 회전하고 같은 홈의 Y를 맞춘다.
   그리퍼는 0.65rad를 유지하며 마지막 D-Y에서 멈춘다. 연속 모드도 매 맞춤 위치에서 새 OK를 기다린다.
   이전 한 방향 맞춤 경로는 다시 계획한다. 맞춤 경로는 수동 조정을 위해 계획 후 30분 안에 사용한다.

기존 A3 선택 파일은 보존하고, 새 판은 `cube_plate_v1` 전용 선택·경로 파일을 사용한다.
기본 거리·방향이 달라지면 이전 판 선택을 백업하고 다시 선택한다. 같은 배치에서 사용자가
입력한 XY 미세 보정은 다음 GUI 실행에서도 유지하며, 좌표를 바꾸면 기존 경로는 다시 계획해야 한다.

검증 범위는 두 승인 방식의 가상 실행·정지, 네 모서리 전체 가상 순회 완료, 3층 공중 팔 경로 계획이다.
**이 업데이트에서 실제 팔 목표는 보내지 않았으며, 실물 전체 블록 쌓기·파지 성공은 검증하지 않았다.**

### 로봇 없이 화면에서 동작 보기

로봇 전원·랜선·그리퍼 USB 없이 다음 한 줄로 RViz와 가상 로봇 GUI를 함께 실행한다.

```bash
~/ur5e_ws/start_block_sim.sh
```

가상 제어기는 `GenericSystem`만 사용하고 ROS domain **42**에서 동작한다.
실물 실행 스크립트의 domain **0**과 분리되어 있으며, 실물 드라이버를 시작하지 않는다.
420×297mm 플레이트와 선택한 쌓을 홈, 16mm 받침대를 표시한다.
가상 팔은 `home` 자세, 그리퍼는 **0.4rad**에서 시작한다.

1. **「간단한 3층 예시」**를 누르거나 **「쌓을 칸」**으로 바닥 블록이 있는 목표 홈을 선택한다.
   3층 예시는 21번 바닥 블록 위에 4·13번의 블록 2개를 쌓는다.
2. **「선택 배치를 RViz에 표시」** → **「전체 경로 / 높이 확인」** 순서로 누른다.
3. 실행 방식을 **「단계별 확인」** 또는 **「전체 연속 실행」**으로 선택한다.
4. **「⑤ 선택한 방식으로 가상 실행」**을 누른 뒤 표시된 경로를 확인하고 상단 **OK**를 누른다.
   단계별 모드에서는 구간마다 OK를 눌러야 한다. 연속 모드는 한 번 승인하면 전체 동작을 진행한다.

모서리 홈 동작은 **「플레이트 맞춤 · 모서리 홈」 → 가상 실행 → OK**로 확인한다.
그리퍼 0.65 준비 동작도 단계별 모드의 첫 번째 승인 구간에 포함된다.
첫 홈 A에 도착하면 모든 실행 방식에서 조정을 위해 멈춘다. 판을 맞추고 손을 뺀 뒤
**「조정 완료 · OK로 계속 이동」**을 누른다. 연속 모드의 나머지 홈 이동은 이 승인 뒤 진행한다.

종료는 실행한 터미널에서 `Ctrl+C`를 누른다. 이는 RViz의 기구학적 블록 쌓기 시각화이며,
중력·마찰이나 실물 파지 성공률을 계산하는 물리 시뮬레이션은 아니다.

### 장애물 위 XY 순회 경로 — 블록 없는 팔 시운전

현재 모델은 **25×25×25mm 블록**, **25×25×150mm 세로 장애물**, 로봇 하부
**16mm 받침대**, 그리퍼 직결 장착(추가 어댑터 없음)을 기준으로 한다. XY 순회에는
블록을 놓거나 집을 필요가 없다. 장애물 상단을 기준으로 한 높이 여유의 기본값은
**50mm**이며 GUI에서 30~100mm 범위로 설정한다.

사람과 불필요한 물체를 동작 범위에서 치우고, 선택한 장애물의 실제 위치와 비상정지
접근을 확인한 뒤 실물 연결을 시작한다. 이 명령은 **그리퍼 초기화 중 손가락을 움직일 수 있다**.
앞의 기본 실습용 launch가 실행 중이면 팔이 멈춘 상태에서 종료하고 아래 통합 실행을 사용한다.

```bash
~/ur5e_ws/start_block_robot.sh allow_execution:=true
```

다른 터미널에서 기존 GUI를 실물 환경으로 연다. 두 스크립트는 기존
`~/ur5e_ws`와 MoveIt 환경을 불러오므로 ZIP 작업공간을 추가로 source하지 않는다.

```bash
~/ur5e_ws/start_block_gui.sh
```

1. GUI에서 판 중심과 장애물 칸을 실제 배치에 맞춘다. 장애물 높이는 150mm,
   높이 여유는 우선 기본값 50mm로 확인한다. 장애물을 선택하지 않으면 7번 칸을
   장애물로 가정하므로 실제 위치에 맞게 선택한다. 쌓을 칸이나 블록 선택은 XY 순회에 필요 없다.
2. 상단 실행 방식을 **「단계별 확인」** 또는 **「전체 연속 실행」**으로 선택한다.
   처음 확인할 때는 기본값인 단계별 확인을 사용한다.
3. **「장애물 위 XY 순회 경로」**를 누른다. 이 버튼은 경로를 계획하고 저장한다.
   계획 중에는 실제 팔에 이동 목표를 보내지 않는다.
4. RViz에서 저장된 전체 경로를 확인한다. 첫 구간은 **현재 그리퍼 방향을 유지한 수직 상승**이다.
   충분히 올라간 뒤 그리퍼 접근 방향을 아래로 맞추고, 같은 높이에서 24개 셀 중심의 XY를
   지그재그로 각각 한 번 방문한다. 계획은 그리퍼 전체 충돌 형상의 하단 높이를 검사한다.
5. **「⑤ 선택한 방식으로 팔 경로 실행」**을 누르고 실행 확인창을 검토한다.
   확인창을 수락한 뒤에도 첫 경로의 OK를 기다리며, 팔은 자동으로 출발하지 않는다.
6. 표시된 경로를 보고 상단 **「확인 OK · 표시한 경로 실행」**을 누른다.
   단계별 확인에서는 수직 상승·자세 맞추기·각 셀 이동마다 다음 경로를 보고 다시 OK를 누른다.
   전체 연속 실행에서는 전체 경로의 OK 한 번으로 순회를 진행한다.
   실행은 검토한 저장 경로를 사용하며 그리퍼 개폐 명령을 보내지 않는다.

순회 경로에는 하강·집기·쌓기·시작점 복귀가 없다. **마지막 셀에 도달한 자세를 유지한다**.
배치·속도·높이 여유·보정 또는 현장 설정을 변경하면 경로를 다시 계획하고 확인한다.
중지가 필요하면 GUI의 **「실행 중지」**를 누르고 팔 정지 확인을 기다린 뒤 창을 닫는다.

이 절차는 실물 시운전 준비용이다. 실제 UR5e에서 해당 XY 순회를 완료했다는 검증 기록은 아직 없다.
